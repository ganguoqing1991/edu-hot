# 教育HOT — 把 AIHOT 开源框架改成教育热点站

> 一句话：**界面一行没删，代码只动了 22 个文件里的 56 处文案；信源、分类、精选标准全部换成了教育行业的。**
>
> **分类从 6 个扩到 8 个**：在「解读」后面**加了两栏**——`竞品`（竞品账号动态）与 `日历`（行业日历与节点）。这两栏**没有改任何界面代码**，因为筛选栏是从 `taxonomy.ts` 的 `CATEGORIES` 自动推导出来的。配套新增了 `industry/calendar.json`（全年节点与真实日期）与 `tools/calendar-lookahead.mjs`（查「未来 N 天该准备什么」）。
>
> **界面与配色跟 AIHOT 源文件保持一致**：`apps/web/app/app.css` 等所有样式文件**一处未动**，站点主色仍是上游的青绿 accent，没有换成品牌金。改的只有文案与逻辑。品牌图只落在 `industry/brand/`（favicon、PWA 图标、`/logo.svg`），位于接口白名单里但不参与界面渲染，所以换图不影响观感。

原项目 `AIHOT` 的设计是「一个行业包搞定一切」——`industry/` 文件夹里的东西换掉，代码基本不用动。这份改造就是按它的规矩做的，只在少数几个**硬编码在代码里**的界面文案上做了必要补丁。

## 三步上手

```bash
# 1. 把原仓库放在当前目录的 AIHOT-main/ 下，然后：
bash apply.sh AIHOT-main

# 2. 复制环境变量，填上模型和数据库
cd AIHOT-main && cp .env.example .env

# 3. 起站
docker compose up --build
```

`apply.sh` 做三件事：备份原 `industry/` → 覆盖为新行业包 → 运行 `patch-repo.mjs` 打补丁 → 跑 `check_pack.mjs` 自检。

**不想用脚本的话**，手工就两步：把 `industry/` 整个覆盖过去，然后在仓库根目录跑
`node tools/patch-repo.mjs`（把 `tools/` 里的两个脚本也拷进仓库根目录的 `tools/`）。

| key | 显示名 | 日报分节 | 备注 |
|---|---|---|---|

| `admission` | 升学 | 升学节点与招生动态 | |
| `sentiment` | 舆情 | 家长情绪与舆情焦点 | |

| `guide` | 解读 | 内容风向与解读 | |

**9 个内容类型**，对应下面精选标准的权重表：
`policy_release` 政策发布 · `admission_update` 升学招生 · `institution_move` 机构监管 · `market_business` 行业经营 · `parent_sentiment` 家长舆情 · `practitioner_voice` 一线自述 · `guide_explainer` 解读攻略 · **`competitor_move` 竞品动作** · **`calendar_node` 日历节点**

**三张标签白名单**：12 个分类标签（政策/监管、升学/招生、家长/舆情、一线/从业者、机构/经营、学校/建设、行业/市场、解读/攻略、内容/风向、**竞品/账号**、**日历/节点**、其他）· 42 个主题标签（19 个常态主题 + **7 个竞品动作** + **16 个日历节点**）· 14 个实体标签（教育部、重庆市教委、重庆教育考试院、七龙珠、学而思、新东方、小红书、抖音、**视频号**、**芥舟语文**…）。

**14 个机构名录**：主管单位（教育部 / 重庆市教委 / 重庆教育考试院）、学校（七龙珠，含七所直属校别名）、机构（学而思、新东方、作业帮、猿辅导、高途、中公、粉笔）、平台（小红书、抖音、**视频号**）、**对标账号（芥舟语文）**。配套的 `IDENTITY_LEXICON` 用来防止模型在标题摘要里写进原文没提到的单位——`芥舟语文` 也进了这份词典，所以它出现在标题里时模型不能凭空引用。

### 3. 主题目录（`industry/topics.json`）

**40 个主题**，分三组（分组 key 沿用 `company`/`field`/`genre`，只改了显示名）：

- **机构与学校**（14）：教育部、重庆市教委、重庆教育考试院、七龙珠、学而思/好未来、新东方、作业帮、猿辅导、中公教育、粉笔、小红书教育内容、抖音教育内容、**芥舟语文**、**视频号教育内容**
- **学段与赛道**（15）：幼升小、小升初、中考、高考、双减与监管、招生政策、学区与划片、民办学校、集团化办学、艺体特长、心理健康、教师减负、机构经营、私域获客、内容运营
- **内容形态**（11）：政策文件、升学招生、家长舆情、一线声音、机构动态、学校建设、行业与市场、解读攻略、内容风向、**竞品账号动作**、**行业日历与节点**

> 那两个新主题（`jingpin-zhanghao`、`rili-jiedian`）挂在 `genre` 组里，**没有新开第四组**。原因是分组被三处硬编码锁死：`apps/web/app/routes/topics.tsx` 的 `GROUPS`、`packages/backend/src/publication/topics.ts` 的联合类型、以及迁移文件 `0002_events_reports.sql:152` 的 `CHECK (grp IN ('company','field','genre'))`。为省一个分组去动核心代码和改数据库约束，不划算。

### 4. 精选标准（`industry/prompts/selection-score.md`）—— 这份是核心

保留了 AIHOT 的骨架（五轴打分 + 类型权重 + 噪声压制 + 输入安全边界 + 单字段输出），把「什么算重要」整个换成了教育行业的口味：

**五轴**：`sig` 实质份量 · `nov` 信息增量 · `cred` 证据强度 · `reson` 共振面 · `act` 可用性

**类型权重表**（每行和为 10，天然落在 0–100）：

| 类型 | sig | nov | cred | reson | act |
|---|---:|---:|---:|---:|---:|
| policy_release 政策发布 | 3 | 2 | 3 | 2 | 0 |
| admission_update 升学招生 | 3 | 1 | 2 | 3 | 1 |
| institution_move 机构监管 | 3 | 2 | 2 | 2 | 1 |
| market_business 行业经营 | 2 | 2 | 2 | 3 | 1 |
| parent_sentiment 家长舆情 | 2 | 2 | 1 | 4 | 1 |
| practitioner_voice 一线自述 | 2 | 3 | 1 | 3 | 1 |
| guide_explainer 解读攻略 | 1 | 1 | 1 | 3 | 4 |
| **competitor_move 竞品动作** | 2 | 2 | 1 | 3 | 2 |
| **calendar_node 日历节点** | 3 | 1 | 3 | 3 | 0 |

> 两行新权重的理由：**竞品**的 `cred` 只给 1，因为账号数据（赞藏数、涨粉数）大多无法核验，不能当事实给分；**日历节点**的 `nov` 给 1、`act` 给 0，因为它的价值不在「新」也不在「能马上用」，而在**确定性**（这个窗口什么时候来、谁适用）。

**必须正常评价的价值**：招生方案/政策文件/公示征求意见（改报名条件、划片范围、招生计划、收费标准的）· 学位预警、新校投用、集团化办学 · 考试安排与分数线 · 培训监管动作（查处通报、年检注销、合规红线收紧或放松）· 机构重大经营变化 · **真实的一线自述（有数字或有机制就给高分，没官方背书也算）** · 形成规模或有官方回应的家长诉求 · 反直觉的本地现象 · 🆕 **竞品账号的可观测动作（内容变了、选题跑出来了、账号增删改名）** · 🆕 **有明确起止时间的行业日历节点**。

**必须压住的噪声**：机构招生广告与名师软文（`sig ≤ 2`）· 校园活动通稿（`sig ≤ 3`）· 例行会议表彰挂牌调研（`sig ≤ 3`）· 无信息的情绪吐槽（`nov ≤ 3`）· 民间名校榜单（`cred ≤ 3`）· 个案逆袭鸡汤（`act ≤ 2`）· 教育早报周报打包（`sig ≤ 3`）· 只有预告没有条款（`nov ≤ 3` 且 `cred ≤ 4`）· 🆕 **竞品的二手八卦与拉踩（`cred ≤ 2`，纯搬运内容 `nov ≤ 2`）** · 🆕 **没有日期或作息表的「节点稿」（`sig ≤ 3`）**。

**未成年人与学校的特殊约束**（AIHOT 没有、教育行业必须加的一节）：涉未成年人个案只评行业信号价值不做事实认定（单方指控 `cred ≤ 3`）· 涉具体学校教师的负面指控无官方通报时 `cred ≤ 4` 且不因劲爆抬高 `reson` · 学生成绩排名与家庭隐私不因猎奇加分。

**事件口径校正 6 条**：还原为最强被支持的事件 · **官方文件的「干」不等于「不重要」**（招生方案、学位预警、年检注销名单照给 sig 与 cred）· 一手与转述分清但转述不自动降级 · 强事件不被弱叙事降格 · 长篇数字多不能制造事件价值 · 本地与全国不互相稀释。

### 5. 入选门槛（`industry/selection.ts`）

| 分级 | 原（AI 校准值） | 现 | 理由 |
|---|---:|---:|---|
| `T1` 官方一手 | 60 | **55** | 教委的招生方案、学位预警、注销名单哪怕标题很干也该进 |
| `T1_5` 官方账号与垂媒 | 65 | **62** | 公众号与行业垂媒，质量高于综合媒体 |
| `T2` 媒体与个人 | 76 | **74** | 地方门户教育版面软性通稿多，门槛要守住 |

`understandFloor` 50 → **48**（略降，让「没入选但信息量够」的资料也走精编写法）。

**两栏新增后没有加新门槛**：`selection.ts` 里仍然只有 T1=55 / T1_5=62 / T2=74 三档。两栏各归一档——

- **日历节点走 T1（55）**：校历、考试日程、招生时间表这类材料的出处就是官方，内容再「干」也不该被「不够新」挡掉。
- **竞品账号走 T2（74，最严）**：账号数据无法核验，用媒体级门槛去挡拉踩、二手八卦和纯搬运。

### 6. 行业日历（`industry/calendar.json`）—— 新增，配合「日历」栏

「日历」栏解决的是**「接下来会发生什么、我该提前准备什么」**，这和「今天收进了什么新闻」是两个问题。所以它由两部分组成：

**(a) 站点上的收集**：`competitor` / `calendar` 两栏收的是**真实的报道**——校历发布、考试日程公告、开学通知这类材料经模型判定为 `calendar_node` 后落进「日历」栏。**我没有伪造任何日历条目去填这两栏**：假造一条「2027 年中考 6 月 12 日」当新闻发出来，会污染首页的「今日要闻」，而且 `POST /api/ingest/items` 本来也不接受正文，只能推标题——那是给自己制造噪声。

**(b) 本地的排期表**：`calendar.json` 是一份**结构化的全年节点库**，不参与首页排序，只回答「未来 N 天有什么」。

```bash
node tools/calendar-lookahead.mjs                 # 默认未来 90 天，打印到终端
node tools/calendar-lookahead.mjs --days 120 --out 行业日历-未来120天.md
```

**17 类节点**：开学、期末、半期、月考、选拔考试、中高考、政策、招生、家长会、竞赛、节假日、展会、节令、大促、申报、上新、其他。每类带 `window`（大致落在哪段时间）、`what`（是什么）、`contentPlay`（这个节点上能做什么内容）。「其他」这一类不带标签——它是个筐，不放进 `TOPIC_TAGS` 白名单。

| 2026-11-11 → 11-30 | 秋假：多数区县连休 5 天，11 月中旬起分三批 | 已公布 |
| 2027-01-11 → 01-18 | 第一学期期末复习考试（义务教育） | 惯例 |

| 2027-02-05 → 02-12 | 春节假期（正月初一 2 月 6 日） | 惯例 |

## 竞品与日历怎么进数据（`tools/collector-competitor.mjs`）

「竞品」「日历」两栏建好了，但**不会自己长出内容**——它们是 `external` 信源，站点不抓网，得有人把数据推上来。这个脚本就是那个"人"，已经写好并且实测跑通了：

```bash
# 1) 先干跑，只打印将要发的内容，不碰网络
node tools/collector-competitor.mjs --kind competitor --in obs.json --dry-run

# 2) 确认没问题，真发（需要 .env 里的 INGEST_TOKEN，≥16 位）
node tools/collector-competitor.mjs --kind competitor --in obs.json

# 3) 日历同理
node tools/collector-competitor.mjs --kind calendar --in cal.json
```

输入格式见两个示例文件（`tools/sample-observations.competitor.json` / `.calendar.json`），**一条 accounts[] = 一个账号 + 一个观察窗口**，脚本自动拼出自包含标题：

> `竞品观察｜小红书·芥舟语文：近 7 天 9 条更新，单条最高 12,000 赞，3 条过万赞，涨粉 1,240；选题全部压在「学区政策解读 + 分班考真题」，评论区家长在追问入学材料`

### 三个坑，都已经在脚本里绕开了（都是读源码读出来的）

| # | 坑 | 后果 | 脚本怎么处理 |
|---|---|---|---|
| 1 | **48 小时陈旧判定**（`materials.ts:62,79`） | 竞品周报如果把 `publishedAt` 写成**窗口起始日**（9/22 发 9/22–9/28 的周报），会比发现时间早 6 天 → 判为历史回灌 → **永远不进「今天」，不进事件图，不加热度**。这一栏会看起来"建了但没数据" | `publishedAt` 一律取**快照时刻**（`observedAt`，通常是现在），绝不取窗口起始日；超 48 小时**明确报警**并说明后果 |
| 2 | **正文推不上来**（`ingest/items.ts:19`） | ingest 接口只收 `title / url / publishedAt / author / raw`，**没有 body 字段**；`raw` 也不会被分析提示词读到。所以模型**只拿得到标题** | 标题一律拼成**自包含整句**（平台·账号·窗口·动作·可观测结果），没有数字就不编数字 |
| 3 | **URL 就是身份**（`lib/url.ts`） | 同一个 URL 再次提交、标题变了 → 记为新**修订**并重新走一遍分析。所以"一个账号一个窗口"必须有一个稳定 URL | 汇总条目用 `profileUrl?w=<窗口起始日>`（`w` 是自有参数，不会被归一化删掉）；单独爆款用笔记原始链接 |

### 它怎么处理"没数据可推"

脚本**不会**替你编造。没给 `profileUrl` 的账号跳过并警告；没有日期的日历节点跳过并警告。宁可两栏先空着，也不往里塞假数据——一条假日期推上去，会被当成今天的新闻排在首页。

### typecheck 抓到的真实缺陷（已修）

这是跑类型检查的价值所在——它抓到 3 类**光靠通读代码看不出来**的问题：

| # | 位置 | 问题 | 修法 |
|---|---|---|---|
| 1 | `apps/api/src/routes/v1.ts:65` | 类别兜底值硬编码成旧分类 `"tip"`，而教育分类里没有 `tip` | 改成 `PUBLIC_API_CATEGORY_KEYS[0]`，随分类表自动走，不再硬编码 |

## 设计取舍

- **站名取「教育HOT」**：沿用 AIHOT 的 `{行业词}HOT` 命名法，页面上自然读成「教育日报」。改名只需动 `site.ts` 的 `name` / `homeTitle` / `organization.name` / `mcpPrefix` / `crawlerName`（`mcpPrefix` 要在没人接入前改）。
- **界面配色一律不动**：AIHOT 的视觉是一套完整的青绿 accent 体系，换色会连带改十几处状态色（hover、边框、选中态）。品牌辨识靠 logo 与站名承载就够了，主色保持上游一致，升级上游时也不会产生样式冲突。
- **一线声音单独成类，不并进舆情**：这是你原来那份雷达 skill 的核心判断——官方线告诉你政策是什么，媒体线告诉你发生了什么，只有一线线告诉你真实体感和接下来会怎么走。所以它在 `CATEGORIES` 里独占一个 `practitioner`，在日报里独占一节「一线声音」，在精选标准里有专属内容类型和权重。
- **精选标准里加「未成年人与学校」一节**：AI 行业没有这个风险面，教育行业必须有。不加这一节，模型很容易把「某校某老师的单方指控」评成高分。
- **门槛用「官方松、媒体紧」而不是一刀切**：教育行业的信息结构和 AI 行业相反——AI 的重磅消息多在厂商博客和媒体，教育的硬信息多在红头文件里，而媒体版面反而是软性通稿的重灾区。
- **补丁不改 `key` 只改显示名**：`topics.tsx` 的 `company`/`field`/`genre` 和 `taxonomy.ts` 的类别 `key` 都会进网址和接口，改了会断链。所以只换 label。
- **「竞品」只看账号怎么打，不看机构怎么经营**：机构年检、融资、注销属于「行业」；竞品栏只收**账号级动作**——选题变了、内容跑出来了、账号增删改名、直播话术、投流打法。两者混在一起，模型会把机构新闻当成竞品情报，那样这一栏就没用了。
- **「日历」的价值是确定性，所以它配了一份离线节点库**：新闻流能告诉你「什么时候通知了」，但告诉不了你「下个月有什么」。所以日历栏收报道，`calendar.json` 出排期——**一个负责已经发生，一个负责即将发生**。
- **不伪造日历条目去填栏**：`POST /api/ingest/items` 不接受正文，只能推标题；把未来的日期当新闻推上去，会污染首页「今日要闻」。宁可这两栏一开始是空的，也不制造假数据。
- **不新开第四组主题**：分组被 `topics.tsx` 的 `GROUPS`、后端联合类型、以及一条 SQL `CHECK` 约束三处锁死。为省一个分组去动核心代码 + 改数据库迁移，收益远小于成本，所以两个新主题并入 `genre`。
- **采集和部署解耦**：能把数据搞到手的通道（本机 `xhs` CLI、飞瓜公开榜）都不依赖站点。先攒数据、后建站，这样在花部署成本之前就能判断「这栏情报值不值得养」。
- **小红书走登录态 CLI，抖音走公开榜，两边定位不同**：小红书那条能盯住具体账号（有登录态，能读单账号主页与笔记），但需要一份准确的对标账号清单；抖音那条不需要任何凭证、能直接出「行业头部今天在动什么」，但只有汇总指标、看不了单个作品。**一条管"盯人"，一条管"看盘"**。
- **榜单数字必须标清口径**：榜单给的「点赞增量」和作品的「点赞数」是两个量，混着写就是事实错误。用一个 `metrics.basis` 字段把口径显式带过去，比在脚本里猜语义可靠。
